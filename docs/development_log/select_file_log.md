# select_file 開発記録

## 作成経緯

任意のファイルを指定し、実行できる機能として `select_file` の作成を開始する。

当初は `run_sql` としてSQLファイルを実行する機能を想定していたが、今後SQL以外のファイル形式にも対応できるよう、機能名を `select_file` に変更した。

## 現時点の設計方針

- 格納フォルダ名とファイル名をそれぞれ引数として受け取る
- 第1引数を格納フォルダ名、第2引数を拡張子を含むファイル名とする
- `BASE_DIR` を基準に格納フォルダ名とファイル名を組み合わせ、対象ファイルのパスを生成する
- 1回の処理で実行するファイルは1つのみとする
- 引数が指定されていない場合は入力待ちとし、格納フォルダ名とファイル名の入力を促す
- 現時点（2026/07/16）ではSQLファイルの実行のみ対応する
- 今後必要に応じて、Pythonなど各ファイル形式に対応した実行処理を追加する

## 対象ファイルパスの生成

`select_file.sh` の格納場所を基準に1つ上のディレクトリへ移動し、`SQLStudy` を `BASE_DIR` とする。

第1引数で受け取った格納フォルダパスと、第2引数で受け取ったファイル名を `BASE_DIR` に組み合わせ、対象ファイルの絶対パスを生成する。

例：

`select_file sql/EXISTS test.sql`

第1引数：sql/EXISTS
第2引数：test.sql

生成される対象ファイルパス：

`${BASE_DIR}/sql/EXISTS/test.sql`

これにより、SQLファイルだけでなく、今後Pythonファイルなどを追加した場合も同じパス生成処理を利用できる。



## 単一ファイル実行とする理由

複数ファイルを引数として受け取る場合、引数の個数判定や複数ファイルの実行制御が必要になる。

また、今後任意のファイル形式に対応する場合は、ファイルごとに実行方法が異なる可能性がある。

そのため、対象ファイルを1つずつ指定して実行する単純な構成とし、`select_file` は1回につき1ファイルのみを処理する。



## 今後の検討

ファイル形式ごとに実行方法が異なるため、対応形式を追加する際は拡張子などからファイル形式を判定し、それぞれに対応した実行処理を追加する。
