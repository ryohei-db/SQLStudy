# reset_table 開発記録

## 開発記録を残すことにした理由

- 設計変更や判断した理由を後から見返せるようにするため。
- 完成後に設計資料やREADMEへ反映しやすくするため。
- 試行錯誤した内容を残し、今後の開発でも活用できるようにするため。
- DROP TABLEなどの安全性が重要な処理について、設計判断の経緯を記録し、意図しない実装変更を防ぐため。

---

## 1. 役割の検討

- 指定したテーブルを削除して作り直す関数として設計を開始。
- 最初は複数テーブル対応も検討した。

---

## 2. 設計の見直し

複数テーブル対応を検討したが、以下の理由から見送った。

- DROP TABLE は重大な処理であり、安全性を優先した


そのため

- 1回の実行で削除するのは1テーブルのみ
- 複数削除する場合は繰り返し実行する
- 実行前に y/n の確認を追加する

という設計に変更した。

## 3. 最終方針

- DROP TABLE は重大な操作として扱う
- 1回につき1テーブルのみ削除する
- 実行前に確認メッセージを表示する
- y の場合のみ実行する
- n またはそれ以外は中止する

---

## 実装編 1：入力値とテーブル存在確認

- `init_sql` の実装を参考に、テーブル名を扱う `table_name` 変数を使用。
- 入力されたテーブル名を基に、`sqlite_master` から対象テーブルの存在を確認する方針とした。
- 当初は `CASE` や `EXISTS` の利用も検討したが、まずは処理を動かすことを優先。
- `WHERE` で目的のテーブルを直接検索し、その結果を Bash の条件分岐に利用する構成とした。


## 実装編 2：処理フロー

```text
① テーブル名を入力（実装編 2-1 参照）
        ↓
② sqlite_master を検索（実装編 2-2 参照）
        ↓
③ 検索結果を echo で表示
        ↓
④ Bash の条件分岐（実装編 2-3 参照）
   ├─ テーブルあり
   │      ↓
   │  「DROPしますか？ (y/n)」
   │      ↓
   │   y → DROP
   │   n → 終了
   │
   └─ テーブルなし
          ↓
     「存在しません」
          ↓
         終了
```

---

### 実装編 2-1：テーブル名の取得

引数にテーブル名が指定されているか確認し、指定されていない場合は使い方を表示して終了する。

```bash
if [ -z "${1}" ]; then
    echo "使い方：reset_table 引数（テーブル名）"
    exit 1
fi

table_name="${1}"
```

#### 変数をこの位置で定義する理由

入力値が存在することを確認してから、`table_name` へ値を代入するため。

これにより、空の引数を変数として後続処理で使用することを防ぐ。

### 実装編 2-2：テーブルの存在確認

`sqlite3` で `sqlite_master` を検索し、実行結果を `table_check` へ格納する。

```bash
table_check="$(sqlite3 "${DB}" "SELECT '存在します' FROM sqlite_master WHERE tbl_name = '${table_name}';")"
```

#### コマンドの実行結果を変数へ格納

`sqlite3` の実行結果を利用するため、コマンド置換 `$()` を使用する。

- `$()`：コマンドを実行し、結果を取得する
- `${table_name}`：Bashの変数を展開する

#### SQL内でBashの変数を使用

SQL文全体をダブルクォーテーションで囲み、その中で `${table_name}` を展開する。

`table_name` の値はSQL上では文字列として比較するため、シングルクォーテーションで囲む。

```sql
WHERE tbl_name = '${table_name}'
```

SQL文の末尾には、基本的にセミコロン `;` を付ける。

### 実装編 3-1：条件分岐の整理

テーブルの存在確認と、存在した場合の削除確認は分けて処理する方針とした。

#### 処理の流れ

```text
テーブル存在確認
        ↓
存在する？
├─ 存在しない
│      ↓
│  メッセージ表示
│      ↓
│     終了
│
└─ 存在する
       ↓
   削除確認（y/n）
       ↓
   y → DROP TABLE
   n → 終了
```

- まずテーブルが存在するかを判定する。
- 存在しない場合は、メッセージを表示して終了する。
- 存在する場合のみ削除確認へ進む。
- 削除確認で `y` が入力された場合は `DROP TABLE` を実行し、`n` の場合は終了する。

### 実装編 3-3：削除確認処理の実装

`DROP TABLE` を安全に実行するため、削除前に確認処理を追加した。

- `read` を使用して `y/n` の入力を受け付ける。
- `read` で取得した値は指定した変数へ直接格納されるため、再代入は不要。
- 入力値を `if` 文で判定し、以下の3パターンへ分岐する。
  - `y`：`DROP TABLE` を実行
  - `n`：正常終了
  - それ以外：エラーメッセージを表示して終了
- 条件を追加して判定する場合は `elif` を使用する。
- テーブル名はSQLの識別子であるため、`DROP TABLE` では文字列用のシングルクォーテーションを付けない。


## 最終まとめ

`reset_table` は、指定したテーブルを安全に削除することを目的として実装した。

開発当初は複数テーブルへの対応も検討したが、`DROP TABLE` はデータを削除する重大な操作であるため、安全性を優先し、1回につき1テーブルのみを削除する設計とした。

最終的な処理は以下の流れとした。

```text
テーブル名を取得
        ↓
sqlite_master で存在確認
        ↓
存在する？
├─ No → メッセージ表示 → エラー終了
│
└─ Yes
      ↓
   削除確認（y/n）
      ↓
   ├─ y → DROP TABLE
   │          ↓
   │     成功・失敗を判定
   │
   ├─ n → 正常終了
   │
   └─ その他 → エラー終了
```

実装を通して、`read` による入力受付、BashとSQL間での変数展開、`if` / `elif` による条件分岐、終了ステータス `$?` を利用した成功・失敗判定を取り入れた。

特に削除処理では、処理を実行できることだけでなく、誤操作を防ぐための確認処理を設け、安全性を意識した設計とした。
