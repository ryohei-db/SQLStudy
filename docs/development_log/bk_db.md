# db_bk 開発記録

## 新たな試み

初期実装では else を用いて正常処理をネストしていたが、可読性向上のため Early Exit を採用し、異常系のみを if で処理する構成へリファクタリングした。

## 作成経緯

SQLiteデータベースを定期的にバックアップし、障害や誤操作によるデータ消失に備えるため、`db_bk` の作成を開始した。

バックアップファイルを日時付きで保存し、一定期間経過したバックアップや古い世代を自動的に削除することで、長期間運用しても不要なバックアップが蓄積しない構成を目指した。

---

## 現時点の設計方針

- `BASE_DIR` を基準にデータベースファイルとバックアップディレクトリの絶対パスを生成する
- バックアップ対象は SQLite データベース (`study.db`) とする
- データベースが存在しない場合はエラーメッセージを表示し、処理を終了する
- バックアップディレクトリが存在しない場合は自動作成する
- バックアップファイルは日時付きファイル名で保存し、既存ファイルを上書きしない
- `cp` によりデータベースをバックアップする
- バックアップ結果は終了ステータスで判定し、失敗時は異常終了する
- 30日を超えて保存されたバックアップファイルは自動削除する
- 最新30世代のみ保持し、31件目以降は自動削除する
- バックアップ専用ディレクトリ (`db_backup`) にはバックアップファイルのみを格納する
- 単独実行だけでなく、他スクリプトから `bash` コマンドで呼び出して利用できる構成とする

---

## バックアップパスの生成

`db_bk.sh` の格納場所を基準に1つ上のディレクトリへ移動し、`SQLStudy` を `BASE_DIR` とする。

`BASE_DIR` を基準として、データベースファイルおよびバックアップディレクトリの絶対パスを生成する。

例：


DB

${BASE_DIR}/db/study.db

BACKUP_DIR

${BASE_DIR}/db_backup


これにより、スクリプトの実行場所に依存せず、常に同じ場所を参照できる構成とした。

---

## バックアップファイル名

バックアップファイルは日時付きファイル名として保存する。

例：


study_20260721_120000.db
study_20260721_130000.db
study_20260721_140000.db


ファイル名へ日時を付与することで、過去のバックアップを保持しながら、新規ファイルとして保存できる。

---

## 世代管理方針

バックアップは日時付きファイルとして保存するため、長期間運用するとバックアップファイルが増え続ける。

そのため、

- 30日を超えて保存されたバックアップファイルは削除する
- 最新30世代のみ保持し、31件目以降は削除する

という2段階の管理を行う。

これにより、

- 長期間放置しても不要なバックアップが残り続けない
- 直近のバックアップを一定数保持できる

構成とした。

---

## ディレクトリ構成

バックアップファイルは `db_backup` ディレクトリへ保存する。


SQLStudy
├── db
│ └── study.db
│
├── db_backup
│ ├── study_20260721_120000.db
│ ├── study_20260721_130000.db
│ └── …


`db_backup` はバックアップ専用ディレクトリとし、バックアップファイル以外は配置しない。

---

## 他スクリプトからの利用方針

`db_bk.sh` は単独で実行できるスクリプトとして実装し、必要に応じて他のスクリプトから `bash` コマンドで呼び出して利用する。

呼び出し元では `db_bk.sh` の終了ステータス（`exit 0` / `exit 1`）を受け取り、後続処理の継続可否を判定する。

例：

```bash

bash "${BASE_DIR}/pubfun/db_bk.sh"

if [ $? -ne 0 ]; then
    echo "db_bk.sh の実行に失敗しました"
    return 1
fi

```

この構成により、バックアップ処理、保持期間管理、世代管理を db_bk.sh に集約し、他スクリプトから再利用できる構成とする。
