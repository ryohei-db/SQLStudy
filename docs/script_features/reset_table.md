## reset_table機能

### 概要

- 指定したテーブルを削除する機能
- 対象テーブルの存在を確認し、存在する場合のみ削除処理へ進む
- 削除前に確認入力を受け付け、`y` が入力された場合のみ `DROP TABLE` を実行する
- `.bashrc` の `reset_table` 関数を入口として、`reset_table.sh` を呼び出して実行する

### 主な機能

- テーブル名を引数または対話入力で取得
- `sqlite_master` を利用してテーブルの存在を確認
- テーブルが存在しない場合は処理を終了
- 削除前に `y / n` の確認入力を受付
- `y` の場合のみ `DROP TABLE` を実行
- `n` の場合は削除せず正常終了
- `y / n` 以外の場合はエラー終了
- 終了ステータスを利用して削除の成功・失敗を判定
- 実行結果をメッセージとして表示

### 作成経緯

- テーブルを作り直す際、対象テーブルを削除する処理が必要になった
- 当初は複数テーブルを一度に削除する機能も検討した
- `DROP TABLE` はデータを削除する重大な操作であり、複数テーブルを一括で削除する設計は危険と判断した
- 安全性を優先し、1回の実行につき1テーブルのみ削除する方針とした
- 誤操作を防ぐため、削除前に `y / n` による確認処理を追加した
- 削除結果を明確にするため、終了ステータスによる成功・失敗判定を追加した

### 設計

- `reset_table` 関数はCLIから実行するための入口とする
- 削除処理本体は `reset_table.sh` に分離する
- 引数が指定されている場合は、その値をテーブル名として使用する
- 引数がない場合は `read` を使用してテーブル名を取得する
- `sqlite_master` の検索結果をBashの条件分岐に利用する
- テーブルが存在する場合のみ削除確認へ進む
- `DROP TABLE` の実行前に必ずユーザーの意思を確認する
- 実行結果は `$?` で判定し、正常終了は `exit 0`、異常終了は `exit 1` とする
