# write_shell_log.sh

## 概要

シェルスクリプト実行処理を共通化するためのスクリプト。

各関数から対象シェルスクリプトを直接実行せず、
`write_shell_log.sh` を経由してシェルスクリプトを実行する。

---

## 処理の流れ

```text
呼び出し元(関数)
        │
        ├─ 実行対象スクリプト・引数を渡す
        ▼
write_shell_log.sh
        │
        ├─ 共通設定(settings.conf)の読み込み
        ├─ ログファイル名を生成
        ├─ 実行開始時刻を取得
        ├─ 第1引数から実行対象スクリプトを取得
        ├─ shiftで対象スクリプトを引数一覧から除外
        ├─ 残りの引数("$@")を対象スクリプトへ渡す
        ├─ bashで対象スクリプトを実行
        ├─ 実行結果(SUCCESS / FAILED)をログへ記録
        ├─ exit 0 / exit 1 を返す
        ▼
呼び出し元(関数)
```

---

## 入力

### 関数

```bash
init_sql EXISTS employee
```

### write_shell_log.sh

```bash
bash write_shell_log.sh \
    init_sql.sh \
    EXISTS \
    employee
```

---

## 出力

- シェルスクリプト実行結果
- 終了ステータス
- シェル実行ログ

---

## ログ対象

SQLStudyプロジェクト内で実行するシェルスクリプト

- init_sql.sh
- reset_table.sh
- select_file.sh
- bk_db.sh
- update_readme.sh

---

## ログ対象外

一般的なLinuxコマンド

```bash
ls
pwd
grep
find
cat
```
- `gsave.sh` は、実行後のログ追記によって新たなGit差分が発生するため、シェルログの対象外とする。
---

## 主な役割

- 共通設定の読み込み
- シェルスクリプト実行方法の共通化
- シェルスクリプトの実行
- 実行開始時刻の取得
- シェル実行ログの出力
- 呼び出し元へ終了ステータスを返却

---

## メリット

- シェルスクリプトの実行方法を統一できる
- シェル実行ログを共通化できる
- ログ取得処理を1か所で管理できる
- 保守性・再利用性を向上できる
- 各スクリプトは本来の処理だけに集中できる
