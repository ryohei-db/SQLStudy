## init_sql機能

### 概要

- 指定したフォルダとテーブル名を基準に、対象テーブルの初期作成処理を自動化する機能
- 対象テーブルが存在しない場合のみ新規作成処理を実行する
- `CREATE.sql` から対象テーブルの `CREATE TABLE` 文のみを抽出して実行する
- `INSERT.sql` から対象テーブルの `INSERT` 文のみを抽出して初期データを登録する
- `.bashrc` の `init_sql` 関数を入口として、`init_sql.sh` を呼び出して実行する

### 主な機能

- フォルダ名とテーブル名を引数として取得
- 引数が不足している場合は `read` で入力を受け付ける
- `BASE_DIR` を基準に `CREATE.sql` と `INSERT.sql` のパスを生成
- SQLファイルの存在を事前に確認
- `sqlite_master` を利用して指定テーブルの存在を確認
- 対象テーブルが既に存在する場合は作成処理を行わず正常終了
- `awk` を利用して対象テーブルの `CREATE TABLE` 文を抽出
- CREATE文の抽出結果とSQL実行結果を別々に判定
- CREATE成功後、対象テーブルの `INSERT` 文を抽出
- 同一テーブルに対する複数の `INSERT` 文を抽出・実行
- INSERT文の抽出結果とSQL実行結果を別々に判定
- 対象SQLが存在しない場合はエラーとして処理を終了
- INSERT文の抽出または実行に失敗した場合は、作成済みテーブルを削除して処理開始前の状態へ戻す
- SQL出力とエラーメッセージの出力先を分離

### 作成経緯

- SQL学習時、テーブル作成と初期データ登録を毎回手動で実行する手間があった
- `CREATE.sql` と `INSERT.sql` の実行をまとめて自動化する機能として作成を開始した
- 既存テーブルへの再作成を防ぐため、`sqlite_master` を利用したテーブル存在確認を追加した
- 当初はDB内にテーブルが1つでも存在する場合、処理を行わない仕様としていた
- 複数の学習用テーブルを扱うため、指定テーブル名単位で存在確認を行う仕様へ変更した
- 当初はSQLファイル全体を実行していたが、存在確認は1テーブル単位、SQL実行はファイル全体となっており、処理単位に差があることを確認した
- 存在確認とSQL実行の対象を統一するため、`awk` を利用して指定テーブルのSQLのみを抽出・実行する仕様へ変更した
- 対象SQLが存在しない場合でも `sqlite3` が正常終了し、成功と誤判定する可能性があることを確認した
- SQL抽出結果とSQL実行結果を個別に判定する処理を追加した
- SQLとエラーメッセージが同じ標準出力に混在しないよう、エラーメッセージを標準エラー出力へ分離した
- INSERT処理失敗時に作成途中のテーブルが残る問題を確認し、対象テーブルを削除して処理開始前の状態へ戻す処理を追加した
