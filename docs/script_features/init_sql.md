## init_sql機能

### 概要

- 指定したフォルダの `CREATE.sql` と `INSERT.sql` を実行する機能
- 対象テーブルが存在しない場合のみ初期作成処理へ進む
- `CREATE.sql` を実行してテーブルを作成後、`INSERT.sql` で初期データを登録する
- `.bashrc` の `init_sql` 関数を入口として、`init_sql.sh` を呼び出して実行する

### 主な機能

- フォルダ名とテーブル名を引数として取得
- `BASE_DIR` を基準に対象SQLファイルのパスを生成
- `CREATE.sql` と `INSERT.sql` の存在を確認
- SQLファイルが存在しない場合は処理を終了
- `sqlite_master` を利用して指定テーブルの存在を確認
- 対象テーブルが存在する場合は作成処理を行わず終了
- 対象テーブルが存在しない場合のみ `CREATE.sql` を実行
- テーブル作成後に `INSERT.sql` を実行し、初期データを登録

### 作成経緯

- SQL学習時、テーブル作成と初期データ登録を毎回手動で実行する手間があった
- `CREATE.sql` と `INSERT.sql` の実行をまとめて自動化する機能を検討した
- 既存テーブルに対して再度 `CREATE TABLE` を実行するとエラーになるため、事前にテーブルの存在確認を行う設計とした
- 当初はDB内にテーブルが1つでも存在する場合、処理を行わない仕様としていた
- 複数の学習用テーブルを扱う場合に対応できないため、指定したテーブル名単位で存在確認を行う仕様へ変更した
- SQLファイルの指定ミスを早期に検出するため、`CREATE.sql` と `INSERT.sql` の存在確認処理を追加した
