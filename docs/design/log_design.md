# ログ保存の設計

## 設定

ログ保存に必要な設定値は設定ファイルで管理する。

設定ファイルには処理ではなく、設定値を記載する。

```bash
LOG_DIR=...
LOG_PREFIX=...
LOG_KEEP_COUNT=30
```

実際のログ処理は専用スクリプトへ実装する。

```
log_sql.sh
write_shell_log.sh
```

### 設定ファイル

- リポジトリ（プロジェクト）全体で共通利用する設定を管理する
- `.conf` は設定ファイルを表す一般的な拡張子

```
SQLStudy
├── config
│   └── settings.conf
```

---

## ログファイル

ログは日単位でファイルを分割し、その日のログへ追記する。

```
logs/
├── sql_exec_YYYYMMDD.log
├── shell_exec_YYYYMMDD.log
```

---

## ログ内容

ログには以下の情報を記録する。

- 実行日時
- 対象ファイル名
- 実行時間
- 実行結果（SUCCESS / FAILED）

---

## ファイル作成

ログを書き込むタイミングで、その日のログファイルを作成する。

---

## SQLログ

SQL実行の入口を統一する。

```
SQL実行
    ↓
log_sql.sh
    ↓
sqlite3
    ↓
ログ記録
```

### ログ対象

- `sqlite3` コマンドによるSQL実行

---

### シェルログ

シェルスクリプト実行の入口を統一する。

```text
関数
    ↓
write_shell_log.sh
    ↓
対象シェルスクリプト
    ↓
ログ記録
```

### ログ対象

SQLStudyプロジェクト内のシェルスクリプトを

`write_shell_log.sh`

経由でBash実行した場合にログを記録する。

例

```bash
bash init_sql.sh
bash bk_db.sh
bash select_file.sh
```

### ログ対象外

一般的なLinuxコマンド

```bash
ls
pwd
grep
find
cat
```

---

## エラー時

- 実行結果にかかわらずログを記録する
- ログ書き込みに失敗しても本来の処理は継続する

---

## ログ保持

- 最新30ファイルまで保持する

---

# 今回学んだこと

- 設定と処理を分離して管理する
- ログは必要になったタイミングで作成する（Lazy Creation）
- 処理の入口を1つに統一する
- 最初から共通化せず、重複が見えてから共通化する
- ログはLinux全体ではなくプロジェクト単位で管理する
- ログ機能は補助機能として設計する
- 保持件数を決めてログを管理する
- SQL・シェルともにログ形式を統一する
