# 2026/07/27以降のコーディング方式

本ドキュメントは、ShellCheckによる品質改善を踏まえ、2026/07/27以降に適用するBashコーディング方針をまとめたものである。

既存コードについては、動作への影響や不具合混入のリスクを考慮し、全面的な修正は行わない。
必要な箇所のみ修正し、今後作成・修正するコードから本方針を適用する。

---

## 1. 処理失敗の判定

### 従来

- コマンド実行後に `$?` を使用して終了ステータスを判定していた。

```bash
command

if [ $? -ne 0 ]; then
    exit 1
fi
```

### 今後

- コマンドの実行と判定を一体化し、`if !` を使用する。

```bash
if ! command; then
    exit 1
fi
```

---

## 2. 入力処理

### 従来

```bash
read variable
```

### 今後

- `read -r` を使用する。
- バックスラッシュをそのまま扱い、意図しないエスケープを防ぐ。

```bash
read -r variable
```

---

## 3. 文字列出力

### 従来

- 改行を含む変数の出力にも `echo` を使用していた。

```bash
echo "${sql}"
```

### 今後

- 改行を含む変数を出力する場合は `printf '%s\n'` を使用する。
- 出力内容をより確実に制御する。

```bash
printf '%s\n' "${sql}"
```

---

## 4. テーブル削除

### 従来

```sql
DROP TABLE table_name;
```

### 今後

- `DROP TABLE IF EXISTS` を使用する。
- 存在しないテーブル削除時の不要なエラーを防ぐ。

```sql
DROP TABLE IF EXISTS table_name;
```

---

## 5. エラー出力

### 従来

- エラーメッセージも標準出力へ表示していた。

```bash
echo "エラー"
```

### 今後

- エラーメッセージは標準エラー出力へ出力する。

```bash
echo "エラー" >&2
```
- 標準出力と分離することで、他のスクリプトやコマンドと組み合わせた際に
- 出力結果とエラーメッセージを区別しやすくする。
- これにより他の処理で利用する標準出力の内容にエラーメッセージを混ぜず、エラーだけをターミナル（標準エラー出力）へ表示できる。


---

## 6. ShellCheck対応

### 従来

- ShellCheckを十分活用できていなかった。

### 今後

- ShellCheckの警告内容を確認し、理由を理解した上で修正する。
- 修正による影響が大きい場合は、安全性を優先し、全面的なリファクタリングは行わない。
- 警告を無視する場合は、理由をコメントとして残す。

---

## 適用方針

- 既存コードは動作保証を優先する。
- 必要な箇所のみ修正を行う。
- 新規作成・修正するコードから本コーディング方針を適用する。
- 品質向上と保守性向上を目的とし、ShellCheckを活用した継続的な改善を行う。
