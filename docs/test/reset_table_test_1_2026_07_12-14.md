### reset_table テーブル存在判定の修正

#### 修正前

`sqlite3` の実行結果を `table_check` に格納し、文字列比較によってテーブルの存在を判定していた。

```bash
table_check="$(sqlite3 "${DB}" "SELECT '存在します' FROM sqlite_master WHERE tbl_name = '${table_name}';")"

if [ "${table_check}" = "存在します" ]; then
```

---

#### 発生した問題

`.sqliterc` の設定により、`sqlite3` の実行結果に検索結果だけでなく、ヘッダーや区切り線も含まれていた。

そのため、`table_check` に格納された値が `"存在します"` と完全一致せず、存在するテーブルでも存在しないと判定されてしまった。

---

#### 修正方針

`sqlite3` の表示結果を文字列比較するのではなく、検索結果の有無で判定する方法へ変更する。

---

#### 修正内容

- `sqlite3` の検索結果を `grep -q .` に渡す
- 検索結果が1件以上あれば存在すると判定する
- `.sqliterc` の表示形式に依存しない判定へ変更する

---

#### 修正後の動作

- テーブルが存在する場合は正常に存在すると判定する
- テーブルが存在しない場合のみエラー終了する
- `.sqliterc` の表示設定に影響されず、正しく条件分岐を実行できる

### reset_table 引数引き渡し処理の修正

#### 修正前

`.bashrc` の `reset_table` 関数から `reset_table.sh` を呼び出していたが、引数を渡していなかった。

```bash
reset_table() {
    bash "/mnt/c/DEV/SQLStudy/sqlfun/reset_table.sh"
}
```

そのため、

```bash
reset_table init_reset_test
```

を実行しても、`reset_table.sh` 側では `$1` が空となり、引数が指定されていないと判定されていた。

---

#### 修正方針

シェル関数から別スクリプトを呼び出す際は、関数へ渡された引数も一緒に引き継ぐよう修正する。

---

#### 修正内容

`bash` の実行時に `"$@"` を追加し、関数へ渡された引数を `reset_table.sh` へそのまま渡すよう変更した。

```bash
reset_table() {
    bash "/mnt/c/DEV/SQLStudy/sqlfun/reset_table.sh" "$@"
}
```

---

#### 修正後の動作

- 引数を指定して `reset_table` を実行した場合、`reset_table.sh` へ正しく引数が渡される。
- `reset_table.sh` 側で `$1` にテーブル名が格納される。
- 引数がある場合は入力待ち (`read`) を行わず、そのまま存在確認処理へ進む。
