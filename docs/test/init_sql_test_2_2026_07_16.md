### init_sql 入力待ち後の空入力判定追加

#### 修正前

引数が指定されていない場合は `read` によりフォルダ名とテーブル名の入力を受け付け、そのまま後続処理へ進んでいた。

```bash
if [ -z "$1" ] || [ -z "$2" ]; then
    read folder table_name
fi
```

---

#### 発生した問題

入力待ちで何も入力せず Enter のみを押した場合でも、`folder` と `table_name` に空文字が格納されたまま後続処理へ進んでいた。

その結果、空の値を使用してSQLファイルのパスが生成され、存在しないファイルとして処理が終了していた。

---

#### 修正方針

引数の有無を判定する処理とは別に、`read` 後の入力値が空でないかを判定する。

---

#### 修正内容

- `read folder table_name` の直後に空入力判定を追加
- フォルダ名またはテーブル名が空の場合はエラーメッセージを表示
- 後続処理へ進まず `exit 1` で終了

---

#### 修正後の動作

- フォルダ名・テーブル名の両方が入力された場合のみ後続処理へ進む
- Enterのみ入力した場合はエラー終了する
- 空の値を使用したファイルパスが生成されなくなった

### init_sql 入力待ちで空入力した場合

#### 実行内容

`init_sql` を引数なしで実行し、入力待ちで Enter のみを入力。

#### 実行結果

- 引数が指定されていないため入力待ち処理を実行
- `folder` と `table_name` の入力値を確認
- 入力値が空と判定
- エラーメッセージを表示
- `exit 1` で処理を終了
