### reset_table 入力待ち後の空入力判定追加

#### 修正前

引数が指定されていない場合は `read` によりテーブル名の入力を受け付け、そのまま後続処理へ進んでいた。

```bash
if [ -z "$1" ]; then
    read table_name
fi
```

---

#### 発生した問題

入力待ちで何も入力せず Enter のみを押した場合でも、`table_name` に空文字が格納されたまま後続処理へ進んでいた。

その結果、空のテーブル名を使用して存在確認や削除処理を実行する可能性があった。

---

#### 修正方針

引数の有無を判定する処理とは別に、`read` 後の入力値が空でないかを判定する。

---

#### 修正内容

- `read table_name` の直後に空入力判定を追加
- テーブル名が空の場合はエラーメッセージを表示
- 後続処理へ進まず `exit 1` で終了

---

#### 修正後の動作

- テーブル名が入力された場合のみ存在確認へ進む
- Enterのみ入力した場合はエラー終了する
- 空のテーブル名を使用した存在確認・削除処理を実行しなくなった


### reset_table 入力待ちで空入力した場合

#### 実行内容

`select_file` から `reset_table.sh` を実行し、実行方法に `bash`、実行確認で `y` を入力。
`reset_table.sh` の入力待ちで Enter のみを入力。

#### 実行結果

- `select_file` から `reset_table.sh` を正常に起動
- `reset_table.sh` の入力待ち処理を実行
- `table_name` に空文字が入力されたと判定
- 空入力を検知し、エラーメッセージを表示
- `reset_table.sh` が `exit 1` で終了
- `select_file` が終了ステータスを受け取り、ファイル実行失敗と判定
- エラーメッセージを表示して処理を終了
